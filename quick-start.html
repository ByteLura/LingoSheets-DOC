Quick Start

From import to a game that switches languages, in about ten minutes. This page follows the same order as the Quick Start shipped inside the package.

1. Open the window and run setup

Open Tools > ByteLura > LingoSheets Pro. The first open shows the welcome screen, with quick actions: Run Setup, Open the Hello World Tour, Documentation, and Support.

Click Run Setup. Setup creates one folder, Assets/LingoSheets, holding your settings and a starter string table (6 keys in English, Spanish, German, and French), and wires Play Mode so no code is needed to load them. Running setup again is safe by design: an existing table is left untouched and only missing pieces are created.

Deleting the Assets/LingoSheets folder returns the project to the post-import state. Setup creates nothing outside that folder.

2. See it work

Click Open the Hello World Tour in the same window, press Play, and move through the languages. The greeting card is two bound components — one TextMeshPro label and one uGUI label — switching on their own when the language changes.

One line in the sample is deliberately present in English only. Watch it fall back to English in every other language, then look at the window's Runtime missing keys block to see the miss recorded with its hit count.

3. Make it yours

  1. Export your starter table with Export sheet, or start a sheet from scratch: first cell key, then one column per language code. The full rules are on the Sheet Format page.
  2. Fill in your game's strings. Keep keys stable (for example menu.start, hud.ammo). Code and components refer to keys, never to text.
  3. Back in the window, click Import sheet and choose the file (.csv, .tsv, or .xlsx). The import report tells you exactly what was added, updated, and left unchanged. Keys the sheet does not mention are kept, never deleted.

4. Bind your UI

  • Add a Localized Text (TextMeshPro) or Localized Text (uGUI) component next to any label and set its key. It follows the current language on its own.
  • Add a Language Dropdown component for a ready-made language picker.
  • From code: Localization.Get("menu.start"), Localization.Get("game.score", points), and Localization.SetLanguage(new LanguageCode("es")). The Runtime Use page covers runtime use in full; the API Summary page summarises the calls.

5. Ship complete

Before a release, open the window and read Missing translations: one row per language with its missing count and coverage. Export untranslated hands your translator a sheet containing exactly the gaps. When the filled sheet comes back, import it. The Export and Missing Reports page covers export and the reports in detail.

If something does not look right

  • No string table yet: the window shows an empty state with two actions, Run Setup and Import sheet. Nothing is demanded of you before that point.
  • A sheet is refused: the window's status line names the problem in plain language, for example a first cell that is not key. The Troubleshooting and Support page lists the common cases and the fix for each.
