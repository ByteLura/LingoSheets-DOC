Troubleshooting and Support

Each entry states what happened and the one action that fixes it, in the same plain language the window itself uses.

Setup and window

  • The window shows "No string table yet." — Nothing is broken; no table exists yet. Click Run Setup to create a starter table, or Import sheet to build one from your own file.
  • Verify Install reports a problem — Open Tools > ByteLura > LingoSheets Pro / Verify Install and read the per-check lines in the status line. Each line names one check (assemblies loaded, TextMeshPro present, starter sheet parses, self-test resolution) and whether it passed. Fix the named item, then run Verify Install again. Verify Install writes nothing to your project.
  • Setup was run twice — That is safe by design. An existing table is left untouched; only missing pieces are created.
  • You want a clean start — Delete the Assets/LingoSheets folder. Setup creates nothing outside it, so deleting it returns the project to the post-import state.

Import

  • "This sheet's first cell must be 'key'." — Rename the first column header to key and import again. Header rules are on the Sheet Format page.
  • A language column is refused as duplicated — The sheet lists the same language twice (spelling variants of one code count as the same language). Remove the duplicate column and import again.
  • The report lists keys in the table that are not in the sheet — Those keys were kept, not deleted. If a key was renamed in the sheet, the old key stays in the table until you remove it in the table inspector, and the renamed key arrives as an addition.
  • Numbers or dates look wrong after an XLSX import — XLSX numbers import as plain text and date-formatted cells import as their raw number (Sheet Format). Type such values as text in the sheet and re-import.
  • Only part of a workbook arrived — XLSX import reads the first worksheet only, by design. Move the strings to the first worksheet, or save that worksheet as CSV and import the CSV.
  • A warning names a row with an unclosed quote — The CSV field starting on that row never closes its quote. Fix the quoting in the sheet and re-import; the report's row number points at the field.

Runtime

  • A label shows the key itself — The key resolved through the whole fallback chain and landed on the final step. The key is missing from the table, or empty in the current language, its base language, and the default language. Check the Missing translations block and the Runtime missing keys block in the window during Play.
  • A label shows raw text with braces — A placeholder in that string is malformed, or a named placeholder has no matching value. The defect is counted rather than raised. Check the string's placeholders against the Sheet Format page and the call that supplies values (Runtime Use).
  • Switching language does not move a dropdown, or moves it twice — Pickers in this package stay in step with external switches without raising a second change. If a picker behaves otherwise, confirm it is one of the shipped dropdown components and that no project code is also setting its value in a language-change handler.
  • A language shows the wrong font — Check the font maps in settings (Fonts and Fallback Chains). Mapped languages use the mapped font; unmapped languages return to the component's original font. If a script renders with missing glyphs, map a font that covers that script.
  • Arabic text appears unshaped or left-aligned in a custom label — Shaping and alignment handling are applied by the shipped binding components. A label driven entirely by custom code needs the shaping call itself; see the RTL and Arabic Shaping and API Summary pages. Long mixed-direction documents are outside v1 scope (Honest Limits).

Support
