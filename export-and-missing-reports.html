Export and Missing-Translation Reports

Export

Export writes the active table back to a sheet, using the same header contract as import: key, comment, then one column per language. An exported file can be edited in any spreadsheet application and re-imported with nothing lost.

  • Formats: CSV, or TSV by file extension. There is no XLSX export in v1; XLSX is import-only (Honest Limits). Every common spreadsheet application opens CSV and TSV, and translators may return either CSV or XLSX — both import.
  • The comment column is written back exactly as stored, so translator notes survive the round-trip.
  • Exporting an unchanged table and re-importing the file is a lossless round-trip: the import report reads zero added, zero updated, and every key unchanged.

Export actions live in the home window's Table block: Export sheet writes everything; Export untranslated writes the gaps (below).

Export untranslated

The untranslated-only export writes a sheet containing only the rows that one chosen language is missing, with every other language's text left in place as reference. That file is the translator hand-off: it contains exactly the work that remains, and nothing else.

  • One export is per language. Run it once for each language with gaps.
  • A row counts as missing for a language when its cell for that language is empty. A cell holding only spaces counts as present.
  • When the filled sheet comes back, import it through the normal path (Import and Merge). The merge updates exactly those cells, and the import report confirms the counts.

Each language row in the Missing translations block also carries a shortcut that exports the untranslated sheet for that language directly.

The missing-translation report

The report is built from the table itself, and the home window displays it without recounting. For each language it gives:

  • The count of missing keys.
  • Coverage as a whole percentage (rounded down).
  • The list of missing keys for that language. A key missing in two languages appears in both lists.

The Missing translations block sorts languages with the worst coverage first. When every key is present in every language, the block reads: "Every key is translated in every language."

The runtime missing-key log

The report above describes the table. The runtime log describes your game. During Play, every lookup that resolves past the first step of the fallback chain (Runtime Use) is recorded with:

  • The key.
  • The language that was requested.
  • Where the value actually came from.
  • A hit count, so repeated misses on the same key and language increment a counter instead of filling the list.

In Play Mode the home window shows this log in its Runtime missing keys block, with a Clear button. The log lives in memory only; it is cleared on initialisation and on an explicit clear, and nothing from it is written to disk.

Together the two views answer the two release questions: what is missing from the table, and what did players' language choices actually ask for that the table could not serve directly.
